## 1. 产品概述

### 1.1 背景
用户是深圳的骑行爱好者，常在周末沿深圳海岸线骑行（深圳湾、盐田、大鹏等）。现有通用地图 App 对"沿海骑行"缺乏针对性：不会主动推荐海岸线路线、不便于沉淀个人骑行记录。本产品聚焦**深圳地区沿海骑行场景**，把"规划路线"做成核心，并顺带记录骑行数据。

### 1.2 目标与核心价值
- **核心**：帮用户快速规划一条好骑的深圳沿海路线（距离、用时、海岸线贴合度可控）。
- **辅助**：自动记录每次骑行的时长、轨迹、里程、次数，形成个人骑行档案。
- **情感价值**：把"沿海骑行"变成可积累、可回看的爱好，而不只是一次 GPS 轨迹。

### 1.3 成功指标（MVP 验证用）
- 用户能在一分钟内从打开 App 到看到一条可用沿海路线。
- 单次骑行记录完成率（开始→结束正常生成记录）≥ 90%。
- 周留存 ≥ 30%（基于本机数据，需后期云端才能准确度量）。

## 2. 用户与典型场景

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 沿海骑行者（主用户） | 深圳本地、周末骑行、熟悉城市但不熟海岸线路网 | 快速拿到一条沿海路线 + 记录骑行 |

**场景 A · 周末想骑**：打开 App → 选"深圳湾环线"预设 → 看距离/用时 → 点"开始骑行" → 沿路骑 → 结束 → 生成记录。

**场景 B · 自己规划**：打开 App → 选"自定义" → 设起点（如福田口岸）终点（如深圳湾公园）→ 系统沿可骑行路网规划一条尽量贴海岸的路线 → 保存为"我的路线"。

**场景 C · 回看**：打开"我的" → 看本月骑行次数、总里程、最长一次 → 点某次记录看轨迹回放。

## 3. 功能需求

### 3.1 沿海路线规划（核心）
- **自定义规划**：用户输入起点/终点（地图选点或搜索），调用高德骑行路径规划，返回路线 polyline、距离、预计用时。
- **海岸线偏好**：在规划时提供"尽量贴海 / 最短距离"两种偏好开关；贴海模式通过对途经点施加沿海岸走廊的偏置实现（MVP 用简化策略：途经点优先落在海岸缓冲区，或叠加海岸线 POI 作为必经点）。
- **路线预览**：地图展示路线、起终点标记、距离/用时卡片；支持缩放。
- **保存路线**：命名后存入"我的路线"，供骑行时一键调用。

### 3.2 预设沿海路线库（冷启动）
首屏提供 3–4 条深圳经典沿海路线，降低空白焦虑：
1. 深圳湾公园环线（约 13 km，平坦，新手友好）
2. 盐田海滨栈道线（约 20 km，海景+隧道）
3. 大鹏较场尾–杨梅坑（约 30 km，进阶，周末向）
4. 蛇口–海上世界–深圳湾（约 18 km，城市海岸）

每条预设含：名称、距离、难度、亮点描述、预设 polyline（预先用高德算好并固化，避免每次实时算）。

### 3.3 骑行记录（实时 GPS 轨迹）
- **开始骑行**：进入记录页 → 选定路线（或"自由骑"）→ 点"开始"，请求定位权限，实时采集 GPS 点（建议 3–5 秒一个点，平衡精度与耗电）。
- **骑行中**：地图显示实时轨迹与"跟随"视角、已骑行距离、已用时长、平均速度（可选）。
- **结束骑行**：点"结束" → 自动生成一条记录：轨迹 polyline、总距离、总时长、起止时间、关联路线名（如有）、平均速度。
- **手动补录（兜底）**：信号差/忘开时，可手动填写时长+选择路线生成记录。
- **记录存储**：写入本机 IndexedDB。

### 3.4 骑行历史与统计
- **历史列表**：按时间倒序展示骑行记录（日期、路线名、距离、时长）。
- **统计看板**：累计骑行次数、累计里程、累计时长、本月/本周数据、最长/最快单次。
- **轨迹回放**：点开单条记录，地图回放该次轨迹。

### 3.5 个人中心 / 设置
- 单位偏好（km）、地图偏好（贴海/最短）。
- 清空本地记录（带二次确认）。
- 关于、版本、数据说明（本机存储、隐私提示）。

## 4. 非功能性需求

| 维度 | 要求 |
|---|---|
| 设备兼容 | iOS Safari 14+ / Android Chrome 90+；竖屏优先 |
| 性能 | 冷启动 < 3s（静态托管）；GPS 采集不卡顿；地图瓦片按需加载 |
| 隐私 | MVP 数据全留本机，不上传；明确告知定位权限用途 |
| 离线 | 已保存路线/记录可离线查看；实时规划需联网（高德 API） |
| 可安装 | PWA：可"添加到主屏幕"，有图标与启动图 |
| 耗电 | GPS 采集间隔自适应（移动时密、静止时疏） |

## 5. 信息架构与页面流

```
启动 → 首页（地图 + 预设路线卡 + "自定义规划"入口）
        ├─ 路线规划页（起点/终点/偏好 → 预览 → 保存/开始骑）
        ├─ 我的路线（列表）
        ├─ 骑行记录页（开始/进行中/结束）
        ├─ 历史列表 → 记录详情（轨迹回放）
        └─ 我的（统计看板 + 设置）
```

---

## 6. 数据模型（本机 IndexedDB）

- **Route（我的路线）**：id, name, polyline, distance, duration, preferMode, createdAt
- **PresetRoute（预设路线，预置）**：id, name, distance, difficulty, desc, polyline
- **RideRecord（骑行记录）**：id, routeId?(关联), name, polyline, distance, durationSec, avgSpeed, startedAt, endedAt, source('gps'|'manual')
- **Settings**：units, preferMode, etc.

## 7. 技术架构方案（推荐）

| 层 | 选型 | 说明 |
|---|---|---|
| 前端框架 | React + Vite + TypeScript | 轻量 SPA，构建为静态资源 |
| 地图 | 高德地图 JavaScript API 2.0 | 含骑行路径规划插件（AMap.Riding / Web 服务） |
| 本地存储 | Dexie.js（IndexedDB 封装） | 路线/记录结构化存储 |
| 定位 | 浏览器 Geolocation API | 实时轨迹采集 |
| 托管 | 静态托管（Vercel / 腾讯云静态 / Netlify） | 零后端，MVP 即可上线 |
| 安装 | PWA（manifest + service worker） | 可加到主屏 |

> 高德 API 需申请 Key（JS API 类型），并在控制台配置安全密钥。

## 8. MVP 范围与排除项

**纳入 MVP**
- 预设沿海路线库 + 地图展示
- 自定义起终点骑行规划（贴海/最短偏好）
- 实时 GPS 骑行记录（开始/结束/自动统计）
- 历史列表 + 统计看板 + 轨迹回放
- 本机存储、PWA 可安装

**明确排除（后期）**
- 实时转向导航播报
- 云端账号与跨设备同步
- 社交（分享、排行榜、好友）
- 海拔/坡度详细分析、心率等外设接入

## 10. 风险与开放问题
- **高德"贴海"规划精度**：通用骑行规划不一定贴海岸，需验证途经点偏置策略效果；可能需预置海岸走廊途经点。
- **GPS 漂移**：滨海高架/栈道易漂移，需轨迹平滑处理。
- **地图 Key 成本**：高德对个人开发者有配额，需监控调用量。
- **隐私合规**：若后期上云，需明确告知与授权。
- **开放问题**：是否需要"路线难度自动评级"（基于距离+坡度）？是否要支持导入 GPX？
